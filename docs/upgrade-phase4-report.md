# 第四阶段执行安全与性能验收报告

日期：2026-08-01

状态：代码、本地与隔离云端预发布验收全部通过；第四阶段已于 2026-08-01 正式发布到生产 API 与 Runner；第五阶段 OASIS 保持关闭。

## 本阶段完成内容

1. 专业版长任务继续使用独立 Cloud Run Job，API 只负责冻结输入、预留额度和派发任务。
2. 每次付费运行都会冻结确认后的客户输入与事实，并保存 SHA-256；后续编辑项目不会改变已扣费任务。
3. 原生模型组件现在记录后端、版本、配置版本、随机种子、输入清单哈希、输出清单哈希和状态。
4. 每个阶段保存不含客户原文的检查点；检查点只含阶段、进度、尝试次数、版本、随机种子和哈希。
5. 临时故障第一次发生时进入 `RETRYING`，保留原额度预留并让 Cloud Run 自动重试同一任务；第二次仍失败才退款。
6. 重试复用同一份冻结输入、同一模型版本、同一配置版本和同一随机种子，不创建第二笔扣费。
7. 客户取消后立即阻止报告写入、只退款一次，并在能取得云端 Execution 名称时请求 Google 停止实际容器。
8. 输入和输出清单支持写入私有、版本化 GCS；未配置私有桶时保持关闭，不伪造存储地址。

## 故障与恢复规则

| 情况 | 任务结果 | 客户额度 | 云端行为 |
|---|---|---|---|
| 首次临时故障 | `QUEUED / RETRYING` | 保持原预留，不再扣费 | 同一任务自动重试一次 |
| 第二次仍失败 | `FAILED_RECOVERABLE` | 原预留退款一次 | 停止重试 |
| 永久输入错误 | `FAILED_RECOVERABLE` | 原预留退款一次 | 不浪费一次无意义重试 |
| 客户取消 | `CANCELLED` | 原预留退款一次 | 请求取消实际 Cloud Run Execution |
| 取消后旧工作进程返回 | 保持 `CANCELLED` | 不再变化 | 禁止写报告 |
| 任务超过失效时限 | `FAILED_RECOVERABLE` | 原预留退款一次 | 后续结果禁止覆盖终态 |

## 30 万人性能基线

测试配置：专业版模型、220 轮、5 个竞品、5 个经营方案、9 个价格弹性点，共 14 个方案；不调用网页采集或 LLM。测试设备为 Apple arm64、Python 3.12.13。该结果是核心计算基线，不是客户完整等待时间。

| 模拟人口 | 核心计算总耗时 | 峰值内存 | 人口表实际内存 |
|---:|---:|---:|---:|
| 100 | 2.22 秒 | 92 MB | 0.12 MB |
| 5,000 | 5.97 秒 | 111 MB | 6.07 MB |
| 20,000 | 17.27 秒 | 170 MB | 24.29 MB |
| 100,000 | 77.99 秒 | 454 MB | 121.46 MB |
| 300,000 | 254.16 秒 | 931 MB | 364.38 MB |

结论：30 万人真实逐行进入专业版模型，不是把小样本结果简单乘大。当前 Cloud Run Job 配置为 2 CPU / 4 GiB，纯计算峰值约为内存额度的 23%，本地用时约 4 分 14 秒。完整任务预计仍主要耗时在公开数据采集、外部接口重试和代表性人群研究，而不是 NumPy 计算。

## Cloud Run 计算费用基线

Google 当前列出的 Cloud Run Jobs 默认单价为每 vCPU 秒 0.000018 美元、每 GiB 秒 0.000002 美元；Jobs 按实例整个生命周期计费，最低一分钟。官方价格页：<https://cloud.google.com/run/pricing>

按现有 2 CPU / 4 GiB 配置估算，并假设免费额度已用尽：

- 30 万人纯计算 254.16 秒：约 0.0112 美元。
- 完整任务若运行 1 小时：约 0.1584 美元。
- 若整次任务发生一次完整重试，计算上限约 0.3168 美元。

以上不含 Gemini、Firecrawl、代理服务、Cloud SQL、网络、存储和实际启动时间；最终必须用 Cloud Monitoring 的 `container/billable_instance_time` 与各外部供应商账单核对。

### 本次云验收发现并阻止上线的问题

Firecrawl 匿名模式的 41 次请求只有 2 次成功，38 次返回 429、1 次返回 502。虽然直连网页、YouTube 和其他来源仍产出 11 条有效证据并让任务完成，但证据广度不足以代表目标质量。因此这版没有进入正式环境。

修正策略：Firecrawl Cloud 没有正式 API 密钥时完全关闭，不再消耗匿名限流；公开发现改用现有 Vertex AI 的 Gemini + Google Search Grounding，保存可点击引用和被引用支持的文本片段，并继续保留客户网址直连抓取。Grounding 结果仍只作为公开线索，不能冒充平台后台、成交数据或页面全文。

### Google 引用采集复验

修正后的第二次完整任务再次运行 300,000 人、220 轮并首次执行成功，云执行耗时 18 分 0.27 秒，峰值分钟平均内存 828.53 MiB。15 个检索主题全部完成，无市场采集警告、无 Firecrawl 请求。

去重后得到 76 条有效公开证据：Shopee 13、Lazada 12、TikTok 1、YouTube 20、其他公开网页 30。抽查片段包含泰文价格与评分、噪音和清洗问题、保修与配送、材质与过滤、Xiaomi/PETKIT 对比，也明确识别当前没有 QuietFlow 在泰国的直接品牌证据。

抽查同时发现搜索摘要可能包含配件低价或跨页面汇总，因此新增强制隔离：Google Grounding 与其他 D 级摘要只进入定性报告，不能修改产品/竞品价格、评分或数值选择集；只有独立抓取页面正文且达到 C 级以上的字段才允许丰富选择集。该规则有独立回归测试。

最终保护镜像 `sha256:8f9be7341ac5f0da0f7eec88109a24126fccac3b53ab7fb4282f933cf3b7562e` 已部署到隔离 Runner。随后用上述 76 条证据的真实报告执行云端断言：75 条 Google Grounding 摘要均被识别为“只作定性证据”，数值选择集仍只有原先 3 个已知竞品，没有把 `shopee.co.th` 或 `lazada.co.th` 当成竞品，也没有引入低于 300 泰铢的可疑配件价格。断言结果为 `PASS`。
