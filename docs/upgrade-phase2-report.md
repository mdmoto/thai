# Upgrade Phase 2 report — PopulationSim technical validation

Date: 2026-07-30  
Production default changed: no  
Production deployment: not performed

## Outcome

PopulationSim 0.10.0 is implemented behind the population-synthesis adapter in
an isolated NumPy 1.26 compute image. The API and native runner remain on their
existing NumPy 2 environment.

Three deterministic validations were completed with **300,000 actual synthetic
rows per run**. PopulationSim materially improved the controlled national
region, gender and income margins:

| Metric | Native | PopulationSim |
| --- | ---: | ---: |
| Mean maximum control-margin error | 1.806830 pp | 0.000019 pp |
| Candidate effective sample share | — | 99.48%–99.52% |
| Candidate maximum/median weight ratio | — | 1.15x |
| Candidate zero or negative weights | — | 0 |

All runs converged in four or five iterations. Runtime and compute cost were
recorded but were not used as rejection criteria.

A second full generation reproduced the three population Parquet SHA-256
values exactly. Runtime and peak-memory diagnostics naturally differ between
runs and are stored as separate content-addressed diagnostic objects.

## What improved

The existing generator independently satisfies some margins and uses
region-conditioned income distributions. Those conditional assumptions do not
currently reconcile exactly with the national income-tier margin, leaving a
stable error of roughly 1.8 percentage points even at 300,000 rows.

PopulationSim balances every generated row so the national controls reconcile
nearly exactly without deleting population groups or creating extreme weights.
Each run writes immutable, content-addressed population, person, household,
control-comparison, diagnostics and manifest artifacts.

## What is not yet proved

The seed is still generated by the project's own model. It is not licensed Thai
household microdata. The current model has independent decision units with a
`household_size` attribute; it does not contain real household IDs or
parent/child/member relationships.

For that reason:

- all 300,000 person rows are explicitly marked as having no household
  relationship;
- the household artifact is deliberately empty and marked unavailable;
- household/person consistency fails rather than being silently assumed;
- the backend status remains `synthetic_seed_joint_calibration`;
- production readiness remains false.

The balancing also changes approximately 2.6%–2.7% total variation in the
synthetic `region × gender × income_tier` joint distribution. That comparison is
against another synthetic distribution, not observed truth. Aggregate margins
are demonstrably better, but the real joint population is not yet known.

## Production decision

Keep `POPULATION_BACKEND=native`.

PopulationSim is a successful technical calibration backend, but it must not be
promoted until legally usable Thai microdata (or properly authorized customer
microdata) is available and passes:

- household/member consistency;
- joint-distribution validation;
- identical downstream research-case holdouts;
- report compatibility and rollback checks.

This is an evidence decision, not a speed or cost decision.
